Sistema de Gestión Odontológica Clinikdent v2.0

Documento Técnico Oficial
Este manual técnico describe la arquitectura, componentes, funcionalidades y procedimientos del Sistema de Gestión Odontológica Clinikdent v2.0.
Última actualización: Noviembre 2025

📋 Descripción del Sistema

Clinikdent v2.0 es un sistema integral de gestión para clínicas odontológicas que permite administrar de manera eficiente todos los aspectos operativos, clínicos y financieros de una o múltiples sedes dentales.

El sistema fue diseñado con arquitectura moderna, escalable y segura, utilizando tecnologías web de última generación y mejores prácticas de desarrollo de software.

🎯 Objetivos del Sistema

  • Centralizar la gestión de pacientes, citas y tratamientos odontológicos
  • Automatizar procesos administrativos y reducir errores manuales
  • Mejorar la comunicación entre odontólogos, personal administrativo y pacientes
  • Proporcionar reportes y analíticas para la toma de decisiones
  • Garantizar la seguridad y privacidad de datos médicos sensibles
  • Facilitar la gestión de inventarios y control financiero

Características Principales

El sistema Clinikdent v2.0 incluye más de 15 módulos integrados con más de 200 funcionalidades para la gestión completa de clínicas odontológicas.

🔐 Gestión de Usuarios y Seguridad

  • Autenticación robusta con Supabase Auth
    • Registro y login seguro con bcrypt
    • Autenticación multifactor (MFA)
    • Tokens JWT para sesiones
    • Recuperación de contraseña vía email
  • Sistema de roles y permisos
    • 4 roles: Admin, Maestro, Odontólogo, Paciente
    • Control de acceso basado en roles (RBAC)
    • Permisos granulares por módulo

📊 Esquema Principal de Tablas

👤 Usuarios y Autenticación

-- Tabla principal de usuarios CREATE TABLE usuarios ( id_usuario SERIAL PRIMARY KEY, supabase_user_id UUID UNIQUE, nombre VARCHAR(100) NOT NULL, apellido VARCHAR(100) NOT NULL, email VARCHAR(255) UNIQUE NOT NULL, telefono VARCHAR(20), rol VARCHAR(20) NOT NULL CHECK (rol IN ('admin', 'maestro', 'odontologo', 'paciente')), estado VARCHAR(20) DEFAULT 'activo', fecha_registro TIMESTAMP DEFAULT CURRENT_TIMESTAMP, ultima_conexion TIMESTAMP ); -- Tokens de recuperación de contraseña CREATE TABLE password_reset_tokens ( id SERIAL PRIMARY KEY, usuario_id INTEGER REFERENCES usuarios(id_usuario), token VARCHAR(255) UNIQUE NOT NULL, expiracion TIMESTAMP NOT NULL, usado BOOLEAN DEFAULT FALSE, created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP );

📅 Citas y Agenda

CREATE TABLE citas ( id_cita SERIAL PRIMARY KEY, paciente_id INTEGER REFERENCES usuarios(id_usuario), odontologo_id INTEGER REFERENCES usuarios(id_usuario), sede_id INTEGER REFERENCES sedes(id_sede), servicio_id INTEGER REFERENCES servicios(id_servicio), fecha DATE NOT NULL, hora TIME NOT NULL, estado VARCHAR(20) DEFAULT 'pendiente' CHECK (estado IN ('pendiente', 'confirmada', 'en_curso', 'completada', 'cancelada', 'no_asistio')), motivo TEXT, observaciones TEXT, created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ); -- Historial de cambios de estado de citas CREATE TABLE cita_historial_estados ( id SERIAL PRIMARY KEY, cita_id INTEGER REFERENCES citas(id_cita), estado_anterior VARCHAR(20), estado_nuevo VARCHAR(20), usuario_modificador_id INTEGER REFERENCES usuarios(id_usuario), razon TEXT, fecha_cambio TIMESTAMP DEFAULT CURRENT_TIMESTAMP );

🦷 Historiales Clínicos

CREATE TABLE historiales_clinicos ( id_historial SERIAL PRIMARY KEY, paciente_id INTEGER REFERENCES usuarios(id_usuario), cita_id INTEGER REFERENCES citas(id_cita), odontologo_id INTEGER REFERENCES usuarios(id_usuario), diagnostico TEXT NOT NULL, tratamiento_realizado TEXT, observaciones TEXT, prescripciones TEXT, proxima_cita DATE, estado VARCHAR(20) DEFAULT 'borrador' CHECK (estado IN ('borrador', 'finalizado', 'cancelado')), firma_digital VARCHAR(500), created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ); -- Documentos adjuntos (radiografías, etc) CREATE TABLE historial_documentos ( id SERIAL PRIMARY KEY, historial_id INTEGER REFERENCES historiales_clinicos(id_historial), tipo_documento VARCHAR(50), nombre_archivo VARCHAR(255), ruta_archivo VARCHAR(500), tamaño_kb INTEGER, uploaded_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP );

💰 Pagos y Transacciones

CREATE TABLE transacciones_mercadopago ( id SERIAL PRIMARY KEY, usuario_id INTEGER REFERENCES usuarios(id_usuario), tipo_transaccion VARCHAR(50) CHECK (tipo_transaccion IN ('pago_paciente', 'pago_odontologo', 'pago_proveedor')), preference_id VARCHAR(255), payment_id VARCHAR(255) UNIQUE, external_reference VARCHAR(255), monto DECIMAL(10,2) NOT NULL, moneda VARCHAR(10) DEFAULT 'COP', estado VARCHAR(50), metodo_pago VARCHAR(100), fecha_creacion TIMESTAMP DEFAULT CURRENT_TIMESTAMP, fecha_aprobacion TIMESTAMP, datos_pago JSONB );

📦 Inventario

CREATE TABLE inventario ( id_item SERIAL PRIMARY KEY, sede_id INTEGER REFERENCES sedes(id_sede), categoria_id INTEGER REFERENCES categorias_inventario(id_categoria), proveedor_id INTEGER REFERENCES proveedores(id_proveedor), nombre VARCHAR(200) NOT NULL, descripcion TEXT, cantidad INTEGER DEFAULT 0, stock_minimo INTEGER DEFAULT 10, precio_unitario DECIMAL(10,2), unidad_medida VARCHAR(50), lote VARCHAR(100), fecha_vencimiento DATE, estado VARCHAR(20) DEFAULT 'activo', created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ); CREATE TABLE movimientos_inventario ( id_movimiento SERIAL PRIMARY KEY, inventario_id INTEGER REFERENCES inventario(id_item), tipo_movimiento VARCHAR(20) CHECK (tipo_movimiento IN ('entrada', 'salida', 'ajuste', 'traspaso')), cantidad INTEGER NOT NULL, usuario_id INTEGER REFERENCES usuarios(id_usuario), motivo TEXT, fecha_movimiento TIMESTAMP DEFAULT CURRENT_TIMESTAMP );

📊 Reportes y Analytics

CREATE TABLE reportes_generados ( id SERIAL PRIMARY KEY, usuario_generador_id INTEGER REFERENCES usuarios(id_usuario), tipo_reporte VARCHAR(100), parametros JSONB, formato VARCHAR(20) CHECK (formato IN ('pdf', 'excel', 'word', 'json')), ruta_archivo VARCHAR(500), fecha_generacion TIMESTAMP DEFAULT CURRENT_TIMESTAMP ); CREATE TABLE metricas_sistema ( id SERIAL PRIMARY KEY, fecha DATE NOT NULL, total_citas INTEGER DEFAULT 0, citas_completadas INTEGER DEFAULT 0, ingresos_dia DECIMAL(12,2) DEFAULT 0, nuevos_pacientes INTEGER DEFAULT 0, created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP );

Servidor Backend

🚀 Configuración del Servidor

El servidor backend está implementado en serverSecure.js utilizando Express.js:

const express = require('express'); const cors = require('cors'); const helmet = require('helmet'); const rateLimit = require('express-rate-limit'); const app = express(); const PORT = process.env.PORT || 3000; // Middleware de seguridad app.use(helmet()); // Headers de seguridad app.use(cors({ origin: process.env.ALLOWED_ORIGINS?.split(',') || ['http://localhost:3000'], credentials: true })); // Rate limiting const limiter = rateLimit({ windowMs: 15 * 60 * 1000, // 15 minutos max: 100 // límite de 100 requests }); app.use('/api/', limiter); // Parseo de JSON app.use(express.json({ limit: '10mb' })); app.use(express.urlencoded({ extended: true, limit: '10mb' })); // Archivos estáticos app.use(express.static('public')); // Rutas app.use('/api/auth', require('./routes/authSecureRoutes')); app.use('/api/citas', require('./routes/citaRoutes')); app.use('/api/pacientes', require('./routes/pacienteRoutes')); // ... más rutas // Iniciar servidor app.listen(PORT, () => { console.log(`🚀 Servidor corriendo en puerto ${PORT}`); });

🔐 Middleware de Seguridad

  • Helmet.js - Headers HTTP seguros
  • CORS - Control de orígenes permitidos
  • Rate Limiting - Prevención de ataques DDoS
  • Sanitización de inputs - XSS prevention
  • JWT Authentication - Tokens seguros
  • Express Session - Sesiones en PostgreSQL

Inicio / API REST

API REST

La API de Clinikdent cuenta con más de 200 endpoints organizados en 15+ módulos con autenticación JWT y documentación completa.

🔗 Endpoints Principales

Autenticación (/api/auth)

POST /api/auth/register

Descripción: Registrar nuevo usuario

Body:

{ "nombre": "Juan", "apellido": "Pérez", "email": "juan@example.com", "password": "Password123!", "telefono": "+57 3001234567", "rol": "paciente" }

Respuesta exitosa (201):

{ "success": true, "message": "Usuario registrado exitosamente", "usuario": { "id": 1, "email": "juan@example.com", "rol": "paciente" } }
POST /api/auth/login

Descripción: Iniciar sesión

Body:

{ "email": "juan@example.com", "password": "Password123!" }

Respuesta (200):

{ "success": true, "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "usuario": { "id": 1, "nombre": "Juan", "email": "juan@example.com", "rol": "paciente" } }

Citas (/api/citas)

GET /api/citas/:id_usuario

Descripción: Obtener citas de un usuario

Headers: Authorization: Bearer {token}

Respuesta (200): Array de citas

POST /api/citas

Descripción: Agendar nueva cita

Body:

{ "paciente_id": 5, "odontologo_id": 2, "sede_id": 1, "servicio_id": 3, "fecha": "2025-12-01", "hora": "10:00", "motivo": "Limpieza dental" }
PUT /api/citas/:id_cita

Descripción: Reagendar cita existente

DELETE /api/citas/:id_cita

Descripción: Cancelar cita

Historiales (/api/historiales)

GET /api/historiales/paciente/:paciente_id

Descripción: Obtener historial clínico de un paciente

POST /api/historiales

Descripción: Registrar nuevo historial clínico

{ "paciente_id": 5, "cita_id": 12, "odontologo_id": 2, "diagnostico": "Caries en molar superior derecho", "tratamiento_realizado": "Obturación con resina", "prescripciones": "Ibuprofeno 400mg cada 8h por 3 días" }

Pagos (/api/mercadopago)

POST /api/mercadopago/crear-preferencia

Descripción: Crear preferencia de pago para MercadoPago
